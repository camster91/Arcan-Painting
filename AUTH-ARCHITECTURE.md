# Auth Architecture — Arcan Painting

## Primary Auth System: Local Auth (ACTIVE)

The primary authentication system is the **local-auth** system using httpOnly cookies + argon2 password hashing + PostgreSQL sessions.

### Endpoints
- `POST /api/local-auth/login` — Login, sets `admin_session` httpOnly cookie
- `POST /api/local-auth/logout` — Clears session cookie
- `GET /api/local-auth/me` — Returns current user from session cookie
- `POST /api/local-auth/change-password` — Change password (authenticated)
- `POST /api/local-auth/password-reset/request` — Request password reset email
- `POST /api/local-auth/password-reset/confirm` — Confirm reset with token

### Security Properties
- Tokens: `crypto.randomBytes(32).toString('hex')` — 256 bits of entropy
- Passwords: argon2 hashed, on-login migration for legacy plain-text
- Sessions: 7-day expiry stored in PostgreSQL
- Cookie: `HttpOnly; SameSite=Lax; Secure` (Secure added when AUTH_URL is https)
- Rate limiting: 5 auth attempts per 60s per IP (in-memory, resets on restart)
- CSRF protection: Provided by `SameSite=Lax` cookie policy

## Secondary Auth System: NextAuth/create.xyz (INACTIVE — requires AUTH_SECRET)

The platform-generated `__create/index.ts` includes a NextAuth integration via `@hono/auth-js`. This system is **only activated when `AUTH_SECRET` is set** in environment variables.

### To keep NextAuth DISABLED (recommended for this app):
- **Do NOT set `AUTH_SECRET` in production environment variables**
- The if-block in `__create/index.ts` (`if (process.env.AUTH_SECRET) { ... }`) will be skipped
- All admin auth routes use local-auth only

### Why not use NextAuth as primary?
- NextAuth uses `skipCSRFCheck` from `@auth/core` (platform requirement for Expo/mobile compat)
- The `__create/index.ts` file is auto-generated by the create.xyz platform — editing it risks being overwritten on next deploy
- Local auth is simpler, fully custom, and works well for this single-owner app

### If you want to enable NextAuth:
1. Set `AUTH_SECRET` in Coolify environment variables
2. Be aware that `skipCSRFCheck` is enabled in the NextAuth config (platform default)
3. NextAuth sessions are stored in `auth_sessions` (PostgreSQL), `auth_users`, `auth_accounts` tables
4. The local-auth system would still work in parallel — but pick one to use for UI

## Rate Limiting Note

Rate limits are in-memory only (no Redis). This means:
- Rate limit counters reset on app restart / container redeploy
- Limits are per-process (not shared across multiple instances)
- For production with multiple replicas: implement Redis-backed rate limiting
- Current limits: 5 auth attempts/60s, 5 password reset attempts/60s
